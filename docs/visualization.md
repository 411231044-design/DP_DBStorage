# Визуализация: панели DP_DBStorage

Две панели, которые собираются из живой MariaDB одной командой:

```bat
py -3.12 tools\panels.py
```

Результат — два самодостаточных HTML в `out/panels/` (открываются в браузере
автоматически; можно переслать файл кому угодно — внешних зависимостей и сети
внутри нет):

| Файл | Что показывает |
|---|---|
| `dashboard.html` | карту мира по слоям (интерактив — кнопки слоёв), метрики, топ типов, стримы persistence |
| `dbpanel.html` | панель данных: дерево объектов, сводка `v_world_summary`, последние `db_commands` с результатами, топ предметов |

Скриншоты в README получены этим же генератором (см. «Обновление скриншотов»).

## Как пользоваться

```bat
py -3.12 tools\panels.py                                  :: подключение по умолчанию (локальный стенд)
py -3.12 tools\panels.py --cfg C:\server\profiles\dp_dbstorage.cfg   :: взять подключение из конфига сервера
py -3.12 tools\panels.py --host 10.0.0.5 --user dpstorage --password ... --db dp_storage
py -3.12 tools\panels.py --no-open                        :: только записать файлы
py -3.12 tools\panels.py --client C:\mariadb\bin\mariadb.exe
```

Приоритет параметров: явные аргументы → `--cfg` → значения по умолчанию.
Клиент mysql/mariadb ищется в PATH и стандартных местах установки; пароль
передаётся через переменную окружения `MYSQL_PWD` (в командной строке процесса
не светится).

## Живой режим (intime)

Разовые панели — снимок на момент запуска. Администратору, которому нужно окно
«всегда актуально», служит `--serve`:

```bat
py -3.12 tools\panels.py --serve                          :: 127.0.0.1:8788, обновление 5 с
py -3.12 tools\panels.py --serve --http 8790 --refresh 10 :: другой порт/темп
py -3.12 tools\panels.py --serve --cfg <dp_dbstorage.cfg> :: подключение из конфига сервера
```

Как это устроено и почему именно так:

- localhost-веб-сервер (только stdlib, без зависимостей) отдаёт те же панели,
  но **перестраивает их при каждой загрузке**; страница обновляет себя сама
  (`meta refresh`). Открывается браузером автоматически.
- Свежее данных в базе быть не может физически: плагин пишет их циклами
  `sync_period_sec` (стримы, тени) и `world_save_sec` (построчные снимки).
  Поэтому разумный `--refresh` — 5–10 с; чаще — просто лишние запросы.
- Чтобы несколько вкладок не устроили гонку, сборка панелей идёт под
  блокировкой и кэшируется на 1–2 с.
- `http://…/status.json` — машиночитаемая точка того же снимка (для внешних
  дашбордов/мониторинга): total/слои/предметы/стримы/игроки + время.
- Безопасность: слушается только 127.0.0.1 (наружу не публикуется; пароль
  СУБД никуда не уходит из процесса), доступ к базе — только чтение.

## Что откуда берётся

Панели — только читают базу, которую пишет плагин (см. README «Архитектура»):

| Блок панели | Источник | Кто и когда пишет |
|---|---|---|
| Точки карты | `world_entities` (x, z, layer) | скриптовый снимок мира, каждые `world_save_sec` |
| Метрики «Сущности/Предметы» | `world_entities`, `entity_items` | там же |
| «Стримы persistence» | `shadow_files` | воркер: байтовые потоки движка из кэша, каждые `sync_period_sec` |
| «Игроки (тени)» | `shadow_players` | воркер: разбор кэшевого players.db |
| Топ типов | `entity_items` | скриптовый снимок |
| `db_commands` | `db_commands` | вы пишете (`INSERT`), плагин исполняет и возвращает результат в ту же строку |

## Почему так устроено

**Почему HTML-файл, а не веб-сервер.** Панель — снимок состояния, а не
сервис: у администратора нет лишнего порта и процесса, файл можно отправить в
тикет/мессенджер. Нужен живой интерактив (правки, произвольные запросы) — это
HeidiSQL/любой mysql-клиент; панели не конкурируют с ним, а дают «взгляд
одним кликом».

**Почему данные снимаются заново при каждом запуске, а не обновляются сами.**
Мир меняется только циклами синхронизации (`sync_period_sec`,
`world_save_sec`) — чаще обновляться нечем; свежесть снимка всегда равна
свежести базы. Скрипт детерминирован (фиксированный seed прореживания), то
есть два запуска подряд без изменений мира дают идентичные панели — удобно
сравнивать «до/после».

**Почему слой dynamic прореживается.** На карте Чероруси это ~20 тысяч точек:
браузер тянет, файл растёт. Для карты берётся 2500 случайных (seed=7), в
подписи честно пишется «показано N из M». Остальные слои (транспорт, зомби,
животные, события — сотни точек) показываются целиком. В базе — все строки,
прореживание только визуальное.

**Почему без географической подложки.** Координаты — игровые (метры, X —
восток, Z — север, край карты 15 360), а сетка с подписями осей даёт
ориентир без прав на использование карт-изображений. Подложку можно подложить
свою, доработав `tools/panels.py` (там один SVG-блок).

**Почему только stdlib.** Скрипт должен работать на боевом сервере, где кроме
Python ничего нет: единственная внешняя утилита — стандартный mysql-клиент,
который рядом с MariaDB есть почти всегда.

## Обновление скриншотов README

```bat
py -3.12 tools\panels.py --no-open
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new ^
  --window-size=1180,2340 --screenshot=docs\screenshots\dashboard.png file:///%CD%\out\panels\dashboard.html
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --headless=new ^
  --window-size=1180,980 --screenshot=docs\screenshots\dbpanel.png file:///%CD%\out\panels\dbpanel.html
```

Подойдёт любой headless-браузер (Edge, Chrome, Chromium).
